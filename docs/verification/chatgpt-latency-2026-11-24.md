# ChatGPT 延迟优化验收

验证日期：2026-11-24（Asia/Singapore）。

用户近期一次真实提问，从提交到正文首字约 15.6 秒，其中会话同步约 1.4 秒，发送前准备约 8.0 秒，完成请求至响应流开始约 2.5 秒，流开始后至首字约 3.7 秒。旧实现将这些步骤串行执行，并为每个 HTTPS 请求重新建立连接。

## 修改

- 增加最多四条空闲连接的 HTTPS 连接池，保留系统代理和正常证书验证。完整消费的响应才可复用；超时、未读正文、服务端主动关闭和取消的连接会丢弃。
- 会话同步与发送前准备并行，图片上传也可重叠。准备任一步失败会中断其他准备操作，不提交问题。没有缓存或复用发送前校验结果。
- Windows 上的流读取增加短周期取消检查，避免正在读数据的线程长时间阻塞“停止”。取消、异常和失效连接均不会自动重发 POST。
- 日志增加各 HTTP 阶段耗时、连接复用情况、准备完成与首字耗时，不包含请求或回答正文及登录数据。

## 真实网络结果

测试使用已导入的同一账号、Auto 模型、关闭深度思考和同一条只要求回复 OK 的短问题。通过独立临时本机账号存储和独立网页测试会话，避免改动应用当前每日会话位置。

| 场景 | 正文首字 | 完整回答 |
| --- | ---: | ---: |
| 优化前，搜索开启 | 11.552 秒 | 13.293 秒 |
| 优化后，搜索开启 | 7.804 秒 | 9.348 秒 |
| 最终代码，搜索开启 | 7.868 秒 | 9.144 秒 |
| 最终代码，同会话连续追问，搜索开启 | 6.730 秒 | 7.695 秒 |
| 最终代码，同会话连续追问，搜索关闭 | 5.608 秒 | 6.389 秒 |

首轮前后对比缩短约 32%。只读模型目录请求的旧连接耗时为 1.3～1.7 秒，复用连接后为 0.8～0.9 秒。真实网络验证覆盖系统代理、TLS、连接复用、同会话历史同步及流式完成。

这是当前网络条件下少量样本，不能据此保证每次低于五秒。默认搜索设置仍保持用户原有选择。
